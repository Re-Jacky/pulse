3 Ways to Build This

Each approach has different trade-offs. My recommendation is highlighted.

A

SwiftUI + Swift (Native) ⭐ Recommended

Pure native macOS app. SwiftUI for the popover UI, IOKit/SMC for hardware data, NSStatusItem for the menu bar icon. Looks and feels exactly like a real Mac app — smooth animations, proper vibrancy/blur, respects dark mode perfectly. Best performance, smallest binary.

Pros

  • Native vibrancy/blur (real frosted glass)
  • Best perf — no JS bridge overhead
  • Direct hardware access via IOKit
  • Tiny app size (~2MB)

Cons

  • Requires Xcode + Swift knowledge
  • macOS-only (but that's fine here)
B

Electron + Node.js

Web tech (HTML/CSS/JS) packaged as a Mac app. Use node-sys-info or systeminformation npm package for metrics. Easier to style with CSS — but the "glassy" look requires faking it.

Pros

  • Familiar web stack
  • Easy CSS styling
  • Fast iteration

Cons

  • ~200MB app size (Chromium bundled)
  • Can't get real native blur/vibrancy
  • Higher memory/CPU overhead
  • Ironic: a system monitor that hogs resources
C

Tauri (Rust + WebView)

Rust backend for system data, macOS native WebView for UI. Much smaller than Electron (~10MB), uses OS WebKit. Middle ground — web UI with native performance.

Pros

  • Small binary, low overhead
  • Rust = fast system access
  • Web UI flexibility

Cons

  • Rust learning curve
  • WebView blur is still fake
  • Less mature macOS integration than Swift

My recommendation: SwiftUI Native — you want it to look good, and nothing looks better than real native blur + vibrancy. The glassy aesthetic you picked is only achievable authentically in Swift.
